# File tools — prototype decision

Date: 2026-10-24.

**Decision: do not build a prototype in this pass.**

A prototype is justified when there is credible demand, a plausible ranking gap, and a scoped operation that can be tested honestly. The current file-tool evidence has relative-interest indexes and three US results pages dominated by established PDF brands. Volume, difficulty, and non-US results pages are missing. Building a merge prototype now would spend engineering effort ahead of the evidence the research itself asked for.

The four English tools are the experiment that can create Search Console data. File tools stay in this backlog.

## What would change the decision

1. A Keyword Planner, or an equivalent labeled export, with monthly searches for one primary query per operation and country.
2. A fresh results page for at least one non-US query, with final URLs recorded.
3. A written choice of one operation, with a page-count cap and a file-size cap.
4. Confirmation that the chosen library version still refuses encrypted files rather than pretending to unlock them.
5. No marketing line that promises a specific output size unless the implementation recompresses images and the tests show it can hit that size on the files being promised.

Until those exist, the recommendation remains defer. A prototype is not a launch of a PDF suite.
