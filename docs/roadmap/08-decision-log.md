# Decision log

| Date | Decision | Why | What would change it |
| --- | --- | --- | --- |
| 2026-10-24 | Use Next.js, TypeScript, React, and Tailwind | The repository had no application. Phase 2 had already named that baseline. No competing limitation was found | A concrete platform limit, written down, not a preference for a newer framework |
| 2026-10-24 | Build four English tools, not two | Phase 2 recommended all four as experiments and did not record a blocker for the discount calculator or the case converter | A results page showing that one of them cannot be a useful page, or a maintenance cost that crowds out the first two |
| 2026-10-24 | Keep percentage variants on one URL | They are the same intent and the same formulas. Separate URLs would be near-duplicates | A query with a distinct job to be done and its own evidence |
| 2026-10-24 | Leave the 100-point score blank | Volume and RPM are unknown. Scoring them as zero would invent a ranking | A sourced volume export and a sourced RPM |
| 2026-10-24 | Do not reconstruct SERP URLs | All 53 Phase 2 `result_url` cells are empty, and a current guess is not the historical result | A new results-page collection with final URLs and a new date |
| 2026-10-24 | Do not prototype PDF tools | Relative interest is not volume, and the opened US pages were brand-heavy. See `research/phase-3-file-tools/` | The five conditions in `03-prototype-decision.md` |
| 2026-10-24 | Publish English without a locale prefix | A single locale does not need `hreflang`, and an `/en` copy would duplicate the index | A second locale that is ready to publish |
| 2026-10-24 | Send no analytics until an endpoint exists and consent is granted | There is no collector, and tool inputs must not be stored | A reviewed endpoint and a payload test against that endpoint |
| 2026-10-24 | Do not add ads, accounts, or a database | No eligibility, no content that needs an account, and no data model | A written approval for ads, after the gates in the monetization plan |
| 2026-10-24 | Do not deploy | The brief forbids production, DNS, and paid accounts without authorization | An explicit request to deploy to a named host |
| 2026-10-24 | Keep nine of the ten requested launch locales unpublished | Native-reviewed translations, researched slugs, and Arabic/Japanese presentation checks are missing. Publishing a draft would create the thin localized pages the request forbids. English stays on the unprefixed URLs. See `11-localization-qa.md` and `12-market-validation.md` | A native-approved catalog and cited slugs for a locale, plus a document-level `lang` and `dir` for prefixed pages. Japanese also needs a segmentation decision |
| 2026-10-24 | Add the requested tools as English browser utilities, and do not ship PDF compression | A later product task required working tools. pdf-lib can merge, split, and embed JPG or PNG in the browser. It does not recompress images, so a “compress PDF” control would overstate the result. No server upload was approved | A measured compression method with stated limits, or an explicit decision to accept server-side processing and its retention rules |
| 2026-10-24 | Do not render an ad slot until a provider exists | An empty reserved box shifts the page and looks like a broken placement. No ad account or script was approved | A reviewed provider, a consent flow that covers that provider, and an environment flag that loads only the approved script |
| 2026-11-19 | Purge internal research disclaimers (`tool.evidence`) from public DOM and generate static Open Graph cards | Public guides rendered internal research validation notes ("Not yet validated..."), damaging crawlable content quality. Dynamic/static OG cards improve social engagement without client overhead | A user-facing editorial rationale for explaining research history on an about or methodology page |
| 2026-11-19 | Refine structured data taxonomy with specific application categories and modular schema generator | Generic `UtilitiesApplication` was upgraded to specific categories (`FinanceApplication`, `DeveloperApplication`, `EducationalApplication`, `MultimediaApplication`) with `operatingSystem: "All"` in `lib/schema.ts`, respecting Google rich result guidelines | Changes in Google Search structured data specifications for web applications |
| 2026-11-19 | Deploy machine-readable `llms.txt` and `llms-full.txt` manifests for AI search indexing | AI engines (Perplexity, ChatGPT Search, Claude, Gemini) need standardized markdown indexes and mathematical algorithm references to cite GoEasyTools directly | Evolution of the `/llms.txt` standard or retirement of AI citation engines |
| 2026-11-19 | Upgrade topic routes to category pillars and deploy task-chaining intent bridges | Category hubs previously had minimal text (<20 words). Adding category overviews and use cases creates true pillar hubs, while `ToolIntentBridge` creates an organic PageRank web routing users between related tasks | Redesign of category browse taxonomy or user workflow patterns |

| 2026-11-19 | Install `pdfjs-dist@6.5.438` for client-side PDF rendering | PDF-to-JPG conversion requires rendering pages to canvas. pdf-lib only manipulates structure; it cannot rasterize. pdfjs-dist is Mozilla's standard, actively maintained, and runs entirely in-browser with a Web Worker | A lighter library that covers page rasterization, or removal of the PDF-to-JPG tool |
| 2026-11-19 | Skip Protect PDF tool — pdf-lib lacks encryption | `pdf-lib`'s `SaveOptions` has no password or encryption fields. Adding encryption requires a separate crypto library (e.g. `node-forge`). Unlock PDF works via `ignoreEncryption: true` + re-save. Protect PDF deferred | pdf-lib adds encryption support, or a lightweight pure-JS PDF encryption library is approved |
| 2026-11-19 | Implement Sprint 1 Developer Suite (JWT Decoder, URL Encoder, JSON to TS, JSON to Python, CSV to JSON) | High-volume developer utilities built with 100% pure client-side TypeScript (zero external dependencies). Ensures proprietary payloads, authorization tokens, and private datasets never leave the user's device | Client-side memory limits or deprecation of Web Crypto/TextDecoder APIs |
| 2026-11-19 | Implement Sprint 2 Color & CSS Design Suite (Contrast Checker, CSS Gradient, Color Palette, Box Shadow, Border Radius) | Web design and CSS utilities built using native sRGB relative luminance math (WCAG 2.1 compliance), HSL color wheel angles, and pure CSS string compilers. 100% in-browser, zero dependencies | Changes to W3C WCAG accessibility standards or CSS specification syntax |
| 2026-11-19 | Implement Sprint 3 Advanced Developer & Image Utilities (Regex Tester, Cron Generator, SQL Formatter, Barcode Generator, Image Cropper) | Developer syntax, scheduling, database query, and graphic cropping tools built client-side. Uses native RegExp with ReDoS loop limits, 5-part cron calculators, ANSI SQL tokenizers, 1D barcode binary generators, and HTML5 Canvas coordinate extraction | Browser engine limits or new RFC specifications |
| 2026-11-19 | Implement Sprint 4 In-Browser Audio & Media Processing (Audio Trimmer, Audio Speed Changer, Video to GIF) | Pure client-side audio and video processing using native Web Audio API (AudioContext/OfflineAudioContext), 16-bit PCM RIFF WAV encoders, and pure TypeScript GIF89a frame compilers. Zero server processing, zero heavy external WASM binaries, 100% private | Deprecation of Web Audio API or requirement for longer multi-minute video transcode queues |

Scoring weights and the rule that maintenance points increase as maintenance gets easier are in `01-product-roadmap.md`. They match Phase 2. No sensitivity test has justified a change.

Commercial confidence for the four tools is low: Trends indexes and eight results pages, with volume and RPM unknown. Engineering confidence for the four tools is higher: the formulas, counting rules, and build are in the repository and covered by tests. Those two confidences are not an average.
